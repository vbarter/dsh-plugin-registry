如何发布 dsh 插件

先运行仓库预检，再创建带检查结果的 GitHub Issue。维护者反馈、修复记录和最终结论都留在 GitHub；满足契约的仓库仍会自动发现。

dsh.bundle 与 topic 契约

根目录 package.json 必须声明 dsh.bundle.patch，值为相对路径（不能含 ..）。仓库加上 GitHub topic dsh-plugin。

提交路径：本页预检 → GitHub Issue → 维护者合并到 vbarter/dsh-plugin-registry 后，目录才会更新。

发布前准备

自动发现要求根目录 package.json 声明 dsh.bundle。GitHub Issue 是正式通道，本站不另开账号体系。

{
  "dsh": {
    "bundle": {
      "patch": "./cordis.patch.yml"
    }
  }
}

提交后会发生什么

  1. GitHub 创建公开提交 Issue。
  2. Action 预检仓库，通过则写入目录草稿，否则进入待审队列。
  3. 系统开出审核 PR；按评论修复后在同一 Issue 跟进。
  4. 维护者在 GitHub 合并审核 PR 后，站点数据才更新。
